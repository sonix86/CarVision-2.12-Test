# Проверки сборки — 20 октября 2026

Среда: Windows 10 x64, Python 3.12.14, PyTorch 2.6.0+cpu, torchvision 0.21.0. Фактические зависимости: requirements-lock.txt.

## Что проверено

- `pip check`: нет конфликтов зависимостей.
- `compileall`: исходники компилируются.
- 5 unit tests: примеры баллов из задания и оптимальное сопоставление, 8 цветов на сплошных синтетических цветах, сохранение групп/дубликатов при split, отказ на недопустимой рамке, отсутствие сетевого обращения при inference с заблокированным socket.connect.
- Три вкладки GUI создаются и переключаются без исключений. Собранный EXE создаёт окно `Tashkent CarVision | Offline Studio`; процесс отвечает.
- Синтетический цикл train → best checkpoint → evaluation → confusion matrix выполняется из Python и из перенесённого EXE. Тестовые веса остаются только в outputs, в models и архив НЕ включаются.
- Контрольный реальный снимок из https://github.com/pjreddie/darknet/blob/master/data/dog.jpg используется только для технической проверки детектора, не для обучения. Найдена одна машина с рамкой [460,79,690,164], detection confidence ≈0.812. Марка unknown без обученного классификатора. Выводы Python и EXE совпали; один вызов CPU inference после загрузки модели ≈0.11 секунды. Это НЕ точность на Ташкенте и НЕ полное время передачи фото.
- Полная папка EXE скопирована в путь с пробелом `outputs/Portable Check`. Запуск inference и train выполнен с пустыми PYTHONHOME/PYTHONPATH и PATH, содержащим только Windows/System32: установленный Python в запуске EXE не участвует.
- Генератор отчёта проверен на отдельном явно синтетическом fixture: 6 страниц, все страницы отрисованы и визуально просмотрены, кириллица читается. Этот тестовый PDF не является итоговым отчётом и не включён в поставку.
- Исправлена выявленная ошибка первой сборки: переход с Python 3.12.0 на 3.12.14. Финальный EXE прошёл последующие проверки.

## Что не проверено и не заявляется

- Реальная точность марок/цветов на Ташкенте: нет пользовательских фотографий и настоящего обученного классификатора.
- Полный экзаменационный цикл с телефоном, пересъёмкой экрана, 20 неизвестными фото и лимитом 120 секунд.
- Работа на другом физическом компьютере: проверен перенос между папками на этом компьютере, не отдельное устройство.
- Визуальная проверка GUI через Windows capture: инструмент вернул `FrameArrived timed out` / `window capture timed out`; прошли программные проверки запуска, вкладок и отзывчивости окна.
- Уникальность архитектуры среди других команд, GitHub доступ преподавателя, реальные студенческие вклады/история, финальная сдача/тег.

Исходные инженерные журналы и тестовые файлы находятся в outputs локального проекта; в переносимую поставку намеренно не включаются синтетические модели и неподтверждённые метрики.
