2. Data: scope and provenance

The objective is a list of English (brand, colour) pairs for every visible car in a phone photograph, including Chinese EVs, multiple cars and partial views. Exact model recognition is optional. The active classifier has 82 brand labels and a separate 43-family head. The 325-name catalogue is a requested scope, not 325 trained models; several sparse brands cannot obtain a confirmed prediction under calibration.

The audited brand feature corpus contains 3,851 car crops: 2,205 training, 704 validation and 942 development-test records. It combines public Stanford Cars and attributed Wikimedia/Flickr vehicle photos with a small local phone subset. Public data dominate, so the requirement to rely primarily on own Tashkent phone data has not yet been satisfied.

The current reviewed local export contains 44 objects in 43 available photographs, 13 brands and three outing/source groups; all are TRAIN-only. Missing original files are excluded. This export overlaps historical training data and must not be added to 3,851 as an independent new sample count. Six newer reviewed training objects supplied 36 augmented feature views for the scoped correction head.

Labels use source metadata, visible badges, original-image review and user corrections. An early GAC Aion attribution was corrected to Dongfeng/Aeolus E70 after comparison with independently labelled source images. Predictions are never accepted as ground truth. Some imported public labels remain provisional; the audit does not certify every visual label.

3. Architecture

Multi-car instance masks isolate body evidence from streets and neighbouring cars. General visual backbones supply complementary shape/detail descriptors; small supervised heads are feasible to adapt on CPU. This is the actual 2.12 route, rather than the legacy MobileNet-only design.

Phone-to-answer pipeline

Phone photo -> local resize / optional tiles and mirrored view

COCO Mask R-CNN ResNet50-FPN-v2 -> visible car/truck masks

Mask-aware crop -> frozen DINOv2 ViT-S/14 + frozen CLIP ViT-B/32

768-D DINO descriptor + 512-D CLIP -> normalized 1,280-D features

Own 82-brand cosine head + grouped reference fallback + calibrated gates

Own 43-family head; scoped make correction for Zeekr / Leapmotor / BYD

Parallel own colour ensemble + masked paint / illumination evidence

Per-instance English (brand, colour) list -> GUI / JSON / TXT / annotated JPG

Each cosine head learns class vectors, biases and a logit scale. Probability, margin, absolute similarity, crop geometry and grouped validation support determine whether a result is confirmed. The family head operates with the accepted make; its manufacturer fallback is limited to Dongfeng when the primary make abstains. Low confidence yields unknown or a visibly unconfirmed hypothesis, not a guaranteed answer.

Parameter counts: the make head has 105,043 trainable parameters; the 43-family head has 55084; the additional scoped make head has 105043. DINO encoder state contains 22,056,576 elements. The paired CLIP visual state contains 87849216 elements (state counts, not the whole application). Encoders and detector are frozen in the deployed classifier training.

Colour is independent of make: own VCoR-trained CNN/statistical heads predict eight classes, then visible-paint and scene-illumination evidence are fused. White, black, grey, red, blue, green, brown and yellow are the output vocabulary. Warm light, reflections and windows still cause errors.

Originality and changes in 2.12

Only general-purpose COCO/DINO/CLIP initialization is used. No third-party ready-made car-brand or car-colour classifier and no external inference API are used. Architectural uniqueness relative to classmates must be checked by the student/instructor.

Version 2.12 fixes the detector-only route selecting the wrong classifier, default colour loading, the joint-colour API, paired-encoder hash checks, conflicting labels/duplicate splits and unsafe reuse of a training output directory. Recognition weights are unchanged from 2.11. These engineering fixes are not evidence of an accuracy increase.

4. Training and 5. Evaluation

Training used PyTorch CPU execution with three worker threads in the logged head-fitting scripts. Frozen features were cached. Weighted cross-entropy counters imbalance; label smoothing and public-teacher KL distillation limit forgetting. Views include original/mask-aware crops, synthetic phone degradation, horizontal flips, darker colour casts and family edge cuts. Augmentations stay with their source group.

Validation chooses candidates and calibrates rejection. Both unrestricted new make replacements failed guards; only the calibrated scoped correction was retained. The original encoders were not retrained. The aggregate elapsed time for the complete development history was not recorded; the paint-head time above is one component, not total training time.

5. Confusion, phone tests and error analysis

Current routed make confusion on all 704 validation crops, whole view; row-normalized. All 82 classes are retained, including sparse classes; zero-support rows are blank. Numeric class labels map to page 2; U is abstention. Full integer counts are supplied in the companion CSV. This matrix was regenerated from the active 2.12 checkpoint.

Chinese-brand failures are driven by similar sedan/SUV bodies, limited local rear/night views, small or absent badges, crop/background sensitivity and sparse group support. The E70/GAC mix-up also exposed a reference-label mistake. A high similarity bar is not a calibrated probability of correctness; forcing the top class would convert unknowns into confident mistakes.

Known real-photo diagnostics: Zeekr and Leapmotor make corrections now pass, but the exact Zeekr 007 model is not trained. Voyah and a white Chevrolet Tracker remain wrong/unconfirmed; AIQAR is outside the 82-brand vocabulary. A white BYD Dolphin may be coloured brown. Some parked cars remain too small or occluded. These known cases became training/development evidence and cannot establish generalization.

Historical local rehearsal: 99 photographs were processed, but only a 41-object reviewed subset had usable make/colour references. Version 2.10 achieved 37/41 confirmed makes and 26/41 colours on that known development subset. This is not a 2.12 blind-test score or accuracy over all 99 photos. No defensible prediction of “8 out of 10 new photos” is available.

Engineering verification: 150 unit tests passed; final EXE analysis of six known photographs took 14.8-16.3 seconds per process on this PC, excluding transfer. EXE help, crop selection/export, paired weights and the detector-only route were checked with Python removed from PATH. A second physical PC and a full timed exam rehearsal have not yet been tested.

6. How to run and 7. Reflection

Exact test-day procedure

1. Extract the complete CarVision 2.12 Full archive into a new writable Windows 10/11 x64 folder. Keep CarVision.exe, models and _internal together. Do not install old patches over it. No Python installation is needed for the packaged application.
2. Run CHECK_ON_NEW_PC.cmd once, then disable Wi-Fi and verify a photograph. PASS checks execution, not answer accuracy.
3. Launch CarVision.exe and confirm the title says 2.12 TEST. Transfer the exam photo by the permitted local method; USB avoids dependence on Telegram/internet.
4. Choose Open photo, then Analyse photo once. Review every visible-car row. Copy the English brand/colour pairs using the assignment-answer button; do not substitute a speculative alternative as a confirmed result.
5. Record the answer before seeing the reference. Preserve JSON/TXT/annotated output. Measure the complete transfer-to-answer cycle against the exam time limit.

Command-line alternative inside the application folder

CarVision.exe predict "C:\photos\car.jpg" --mode fast --output outputs\exam
CHECK_ON_NEW_PC.cmd

For development only, after installing requirements: python launch.py predict "C:\photos\car.jpg" --mode fast --output outputs\exam. The older EXAM/midterm wrapper is optional and is not the primary GUI path. Personal training must write to a fresh output folder; it does not automatically update the advanced 82-brand head. Training scripts and recorded selection policies document the specialist lineage.
