# Tashkent CarVision 1.1

Владелец проекта: **София Рахматулаева**. Windows x64, локальный анализ новых фотографий автомобилей, бесплатные библиотеки, без API и подписок. Ссылка GitHub будет добавлена владельцем позднее.

## Важное изменение версии 1.1

По просьбе владельца **ни детектор, ни классификатор не используют готовые веса**. Обе сети обучаются с нуля на вашей разметке. Предобученный COCO-детектор первой версии убран из поставки; ImageNet-веса не загружаются. Код архитектур torchvision используется с `weights=None` и `weights_backbone=None`.

**Настоящий размеченный набор пока не предоставлен, поэтому обученных рабочих сетей в поставке нет.** Кнопка анализа включается после появления собственного `models/detector.pt`. Это не приложение с заранее записанными ответами: после обучения оно принимает любые новые JPEG/PNG/BMP/WebP. Достоверность зависит от данных и измеряется отдельно. Без обучения распознавание марок и рамок обещать нельзя. Обучение с нуля требует больше данных и времени, чем перенос готовых общих весов. Точная модель автомобиля (Cobalt/Malibu) не требуется заданием: нужны марка и цвет.

## Перенос и запуск EXE

1. Скопируйте `TashkentCarVision-Portable.zip` на Windows 10/11 x64 и распакуйте **целиком** в папку с разрешением на запись.
2. Запустите `CarVision.exe` или `Start CarVision.cmd`. Python отдельно не нужен.
3. Слева находятся разделы «Анализ фото», «Разметка», «Обучение», «О проекте».
4. Для распознавания сначала разметьте свои фотографии и обучите обе сети. После этого можно открыть новое фото и нажать «Анализировать».

Не отделяйте EXE от `_internal`, `models`, `data`, `samples`. Интернет для работы, обучения и распознавания подготовленного пакета не используется. Пакет рассчитан на CPU; видеокарта не обязательна. Для исходников и сборки зависимости устанавливаются один раз. Времени обучения и качества без ваших данных мы не заявляем. На другом физическом компьютере требуется отдельная проверка; перенос между папками на этом компьютере проверяется автоматически.

## Примеры фотографий Ташкента

- `samples/Tashkent_Photo_Examples.pdf`: отдельная восьмистраничная подборка — инструкция, шесть реальных городских снимков, лист проверки.
- `samples/images/01.jpg` … `06.jpg`: файлы для непосредственной загрузки в приложение.
- `samples/sources.json`: авторы, исходные страницы, даты, лицензии CC BY / CC BY-SA и ссылки на лицензии.

В «Анализе фото» есть кнопки «Примеры Ташкента» и «PDF с примерами». Фотографии не являются собственными снимками Софии, не имеют автоматически подтверждённого эталона и **не попадают в обучение**. Имя файла у автора может содержать неточную модель: проверяйте видимую эмблему. Это примеры для проверки, а не итоговый экзаменационный отчёт и не равномерный датасет всех марок. Для честной оценки не обучайте сеть на этих же тестовых примерах. Исходники могут заново получить публичные фото командой `python tools/fetch_tashkent_samples.py`; при ограничении Wikimedia подождите и повторите позднее.

## Разметка собственных данных

**Выбор марки вручную нужен только здесь, при подготовке учебных ответов.** В «Анализе фото» пользователь не выбирает ни марку, ни цвет: после обучения сети находят машины и выдают результат автоматически. «Порог марки» — числовой порог уверенности для `unknown`, а не выбор производителя.

1. Собирайте реальные фото Ташкента: передний, задний и строгий боковой ракурс, разные расстояния, день/вечер, несколько машин, перекрытия и пересъёмка экрана телефоном. Обязательно включайте китайские марки. Не снимайте специально лица и номера, не входите на частную территорию.
2. «Разметка» → «Добавить своё фото». Снимок с исправленной EXIF-ориентацией копируется в `data/images`.
3. Обведите каждую различимую машину. Введите марку **по эмблеме**, выберите цвет и сохраните. Марки можно вписывать сверх предложенного списка. Не объединяйте Daewoo/Chevrolet, Jetour/Chery, Omoda/Chery.
4. Для повторных кадров одной машины/сессии задавайте одинаковую группу. Флаг «Одна группа для серии» сохраняет её при открытии следующих фото; без флага новая фотография получает новую группу. Все машины одной фотографии всегда остаются в одной части split благодаря проверке хеша.
5. Источник: `own`, `team:Name`, `public:DatasetURL`. Импортированные подписи проверяйте вручную. Сохранённые рамки зелёные; новая рамка жёлтая. «Отменить последнюю» убирает последнюю добавленную метку, не фотографию.

Пример строки `data/labels.jsonl`:

```json
{"image":"images/example.png","box":[100,80,600,400],"brand":"BYD","colour":"white","source":"own","group":"session-2026-10-20-01"}
```

Координаты `[left,top,right,bottom]` относятся к исходному снимку после EXIF. Изменение размера окна не меняет координат. Восемь классов: `white, black, grey, red, blue, green, brown, yellow`. Silver→grey, beige/gold→brown, orange→yellow. Проверка корректности файла доступна кнопкой «Проверить данные». Редактирование уже сохранённых значений возможно в JSONL; после изменения датасета переобучите сети.

## Обучение, оценка и распознавание

Вкладка «Обучение» запускает последовательно классификатор марок/цветов и детектор рамок. По умолчанию 25 эпох каждому. «Остановить» завершает дочерний процесс; после прерывания необходимо повторить полный запуск и оценку. Checkpoint записывается через временный файл, чтобы отмена не уничтожала предыдущий целый файл.

```powershell
.\CarVision.exe audit --labels data/labels.jsonl
.\CarVision.exe train --labels data/labels.jsonl --output models --epochs 25 --detector-epochs 25
.\CarVision.exe evaluate --labels data/labels.jsonl --models models --output models/evaluation
.\CarVision.exe predict phone.jpg --mode balanced --models models --output outputs
```

Требуются минимум две марки и независимые группы с марками, присутствующими в train. Ориентир задания — сотни машин на марку; для детектора с нуля может потребоваться существенно больше сцен. 80/20 split по группам с seed 3210; одинаковые снимки по SHA256 и повторные сессии не разделяются. Файл `dataset.sha256` предотвращает случайную оценку на изменившихся данных.

Обучение сохраняет `classifier.pt`, `detector.pt`, `split.json`, `dataset.sha256`, `training.json`, `detector_training.json`, `evaluation/metrics.json`, `evaluation/brand_confusion.png`. После обучения перенесите **всю актуальную папку models** в другую сборку или пересоберите ZIP. Синтетические веса из `outputs/smoke-models` использовать как рабочую модель нельзя.

Оценка классификатора — accuracy марки/цвета и confusion matrix на **эталонных вырезках**, не качество поиска машин. Детектор измеряет precision/recall/F1 при score≥0.5 и IoU≥0.5 на validation-сценах в одном масштабе. Это не итоговый балл на новых уличных фото. Validation используется для выбора checkpoint; отдельный независимый phone-test нужно провести вручную.

Режимы анализа: `fast` — весь кадр; `balanced` — кадр и перекрывающиеся фрагменты 768 px; `detail` — дополнительно отражённый кадр. Внутренние обрезанные рамки отбрасываются, координаты восстанавливаются, дубликаты объединяются NMS IoU .45. Больше фрагментов помогает сохранять детали мелких машин, но не гарантирует обнаружение любой машины и может увеличивать ложные рамки. Подбирайте пороги на validation до экзамена; начальные значения: рамка .5, марка .65. Softmax-уверенность не является калиброванной вероятностью правильности.

Результаты автоматически сохраняются в `outputs`: TXT, JSON с рамками/уверенностью/временем/режимом, JPG с рамками. Имена включают время с микросекундами, чтобы новые запуски не перезаписывали предыдущие. Выбор строки выделяет машину. «Копировать ответ» копирует список; «Экспортировать файлы» сохраняет комплект в выбранную папку. Ctrl+O открывает фото; Ctrl+Enter запускает анализ. HEIC заранее экспортируйте в JPEG.

## Архитектура

```text
Новый снимок → EXIF → уменьшение до ≤1920 px → кадр / перекрывающиеся фрагменты
 → SSDLite320 MobileNetV3 Large, 2 класса, обучение С НУЛЯ
 → восстановление координат + фильтр внутренних обрезанных рамок + NMS
 → вырезка каждой машины → MobileNetV3 Small, обучение С НУЛЯ
 → concatenate global average + max pooling (1152)
 → Linear256 + Hardswish + dropout0.3 → brand head + 8-colour head
 → unknown при низкой уверенности → список (brand,colour)
```

Классификатор: AdamW, LR3e-4, decay.01, cosine schedule, weighted brand CE + .5 colour CE, smoothing .05, batch16. Умеренные affine/flip/brightness/contrast без изменения hue. Checkpoint выбирается по `.6 brand_accuracy + .4 colour_accuracy`. Детектор: AdamW LR3e-4, decay.001, batch2, SSD classification+box regression loss, horizontal flip, лучший validation F1. Обе сети используют только вашу разметку. Вспомогательная HSV-функция цвета остаётся в коде как описанный baseline, но при наличии классификатора используется его обученная цветовая голова.

Уникальность архитектуры среди команд необходимо сверить с преподавателем: программа не знает дизайны других студентов. Исходники и модель нельзя передавать другим командам как их собственную работу.

## Установка исходников и сборка

Windows x64, Python **3.12.14** x64 или более свежий исправленный 3.12. Не используйте 3.12.0: первая EXE-сборка обнаружила ошибку упаковки PyTorch. Доступ в интернет нужен для установки библиотек, но не для весов: готовые веса не скачиваются.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe launch.py setup
.\.venv\Scripts\python.exe launch.py gui
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File build.ps1
.\.venv\Scripts\python.exe tools/package_release.py
```

`setup` только создаёт папки. Версии зависимостей: requirements-lock.txt. В переносимом пакете редактируемый код и копия samples находятся в `source`. При клонировании Git-исходников публичные JPG можно заново получить командой `python tools/fetch_tashkent_samples.py`. Тест `tools/smoke_training.py` использует только синтетические изображения и не подтверждает реальную точность. Все технические проверки и ограничения перечислены в VALIDATION.md.
